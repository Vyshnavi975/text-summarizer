# AI Text Summarizer

A small, self-contained text summarization tool with two interfaces — a command-line script and a local Flask web UI. Paste in a long article, report, or block of text, pick a summary length (short / medium / long), and get a concise summary back.

It runs with **zero external dependencies or API keys** out of the box, using a from-scratch extractive summarization algorithm (word-frequency scoring + a simplified TextRank). If you set an `OPENAI_API_KEY` environment variable, it automatically switches to LLM-based abstractive summarization instead — no code changes needed.

## Features

- **Two backends, one interface**
  - **Demo mode (default, no API key needed):** a hand-written extractive summarizer (`summarizer/extractive.py`) that scores sentences by word-frequency (Luhn-style) and a simplified TextRank graph algorithm, then picks the best-scoring sentences and reassembles them in their original order.
  - **LLM mode (optional):** if `OPENAI_API_KEY` is set, summaries are generated by GPT instead, producing fluent abstractive (not just extracted) summaries.
  - The switch is automatic and silent — if an API call fails for any reason (bad key, network error, rate limit), the tool transparently falls back to the extractive summarizer rather than crashing.
- **CLI** (`summarize.py`) — summarize a file or piped stdin text, with `--length`, `--stats`, `--demo`, and `--quiet` flags.
- **Web UI** (`app.py`) — a single clean page: paste text or upload a `.txt` file, choose a length, submit, and see the summary plus compression stats (word/sentence counts, % reduction) and which backend produced it.
- **Adjustable summary length** — `short` (~15% of sentences), `medium` (~30%), or `long` (~50%), scaled to the size of the input document.
- **No heavy NLP dependencies** — the extractive backend uses only the Python standard library (`re`, `math`, `collections`). Flask is the only hard dependency (needed for the web UI only — the CLI works without it).
- **Unit tests** for the extractive summarizer that run in milliseconds, with no API key or server required.

## How the extractive algorithm works

Since this is the always-available "demo mode" backend, it's worth explaining briefly (full code in [`summarizer/extractive.py`](summarizer/extractive.py)):

1. **Sentence splitting** — a regex-based splitter that handles common abbreviations (`Dr.`, `U.S.`, `e.g.`), decimal numbers, and paragraph/heading breaks without pulling in `nltk` or `spacy`.
2. **Word-frequency scoring** — after removing ~150 common English stopwords, each remaining word's frequency is counted and normalized (0–1) against the most frequent word in the document. Each sentence's score is the average frequency-weight of its words — this is the classic Luhn approach to extractive summarization.
3. **TextRank scoring** — sentences are treated as nodes in a graph, with edges weighted by word overlap (log-normalized to avoid favoring long sentences). Sentence importance is then computed with the same iterative random-walk fixed-point algorithm PageRank uses (damping factor 0.85, run to convergence or 50 iterations).
4. **Combined ranking** — the two normalized scores are averaged, with a mild bias toward earlier sentences (since leads often carry the thesis in article writing).
5. **Selection** — the top-N sentences (N depends on the `--length` setting) are picked, then **re-sorted back into their original order** so the summary reads coherently rather than as a jumbled list of "top" sentences.

This is a real, working implementation of a well-known class of algorithm — not a stub — and it produces genuinely readable summaries, as shown below.

## Setup

Requires Python 3.9+.

```bash
cd text-summarizer
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

`requirements.txt` installs Flask (for the web UI) and pytest (for the tests). The CLI's extractive summarizer needs **no packages at all** — you could run `summarize.py --demo` with just a stock Python 3 install.

To enable LLM-based summarization, set this environment variable before running:

```bash
export OPENAI_API_KEY="sk-..."            # uses GPT
```

and install the optional SDK (uncomment it in `requirements.txt`, or `pip install openai`). If no key is set, the tool automatically runs in demo mode — this is the default and requires nothing extra.

## Usage

### CLI

```bash
python summarize.py --file sample_articles/urban_beekeeping.txt --length short
```

Options:

| Flag | Description |
|---|---|
| `--file`, `-f` | Path to a `.txt` file to summarize. If omitted, reads from stdin. |
| `--length`, `-l` | `short`, `medium`, or `long` (default: `medium`). |
| `--demo` | Force the offline extractive summarizer, even if an API key is set. |
| `--stats` | Print word/sentence counts and % reduction after the summary. |
| `--quiet`, `-q` | Print only the summary text (useful for piping into other tools). |

You can also pipe text in directly:

```bash
cat my_article.txt | python summarize.py --length medium
```

### Web UI

```bash
python app.py
```

Then open **http://127.0.0.1:5000** in a browser. Set `PORT=8080` to change the port, or `FLASK_DEBUG=1` for auto-reload during development.

**The web UI flow, described:**

1. You land on a single page titled "AI Text Summarizer," with a badge near the top showing which backend is currently active — e.g. *"Active backend: Extractive algorithm (demo mode — no API key set)"*.
2. A large textarea invites you to paste an article. Below it, a divider ("— or —") separates a file input where you can instead upload a `.txt` file (max 2 MB) — uploading a file takes priority over pasted text if both are provided.
3. Three radio buttons let you pick the summary length: **Short**, **Medium** (default), or **Long**, styled as pill-shaped toggle buttons.
4. Clicking **Summarize** submits the form. If the input is empty or too short (under ~20 words), an error banner explains what's needed and the page redisplays your input so nothing is lost.
5. On success, a results panel appears below the form showing:
   - The summary text itself, in a bordered, easy-to-read box.
   - A small green tag stating which backend generated it (e.g. *"Generated with: Extractive algorithm (demo mode — no API key set)"* or *"Generated with: OpenAI (LLM mode)"*).
   - Compression stats: original word count → summary word count, original sentence count → summary sentence count, and the overall percentage reduction (e.g. "929 words → 98 words", "89.5% shorter").
6. Your original pasted text stays in the textarea after submitting, so you can tweak the length and resubmit without retyping anything.

## Design notes / choices

- **Why extractive-by-default rather than a stub LLM call?** A portfolio project that only works when you plug in a paid API key isn't very demonstrable. The extractive backend is a real, from-scratch implementation of a classic NLP technique (word-frequency + TextRank), so the project is fully functional and inspectable with nothing but a stock Python install.
- **Why offer LLM mode at all, then?** To show the natural extension path — the same `summarize()` function transparently upgrades to abstractive, fluent summaries when a key is present, with graceful fallback on any failure (bad key, no SDK installed, network error, rate limit) rather than crashing the CLI or web request.
- **Why regex sentence splitting instead of nltk/spacy?** Keeps the project dependency-free for its core functionality (`pip install -r requirements.txt` only pulls in Flask + pytest). The splitter still handles common real-world cases: abbreviations (`Dr.`, `U.S.`), decimals (`3.14`), and paragraph/heading boundaries.
